# Agent guide (short)

A NixOS + home-manager flake for one laptop, `aspire`, user `boatette`. This is the short version for local models. `CLAUDE.md` has the full guide: read the section you need from it when a task touches something not covered here.

## Rules

- Make the smallest edit that does the job, in the style of the file around it.
- Search before writing: `grep -rn '<name>' modules packages`. The value or helper may already exist.
- Never edit `flake.nix`. It is generated by `nix run .#write-flake`.
- Never run `nrs`, `nrb`, `nrt`, `nup`, `nixos-rebuild switch` or `nix flake update`. Evaluate or build instead.
- Never write a hex colour, font name, username or monitor name by hand. Read it from `inputs.self.constants` (`modules/system/constants.nix`).
- New files must be tracked by git before nix sees them: `git add -N <file>`.

## Layout

- Every `.nix` file under `modules/` is a module that is imported automatically. A file adds to one of:
  - `flake.modules.nixos.aspire`: the system
  - `flake.modules.homeManager.boatette`: the user's home config
  - `flake.modules.nvf.nvim`: neovim
- One program per file: `modules/programs/<name>.nix`, with extras in `modules/programs/<name>/`.
- Services: `modules/services/`. Machine: `modules/hosts/aspire/`. Local packages: `packages/<name>/package.nix`, used as `pkgs.local.<name>`.
- To disable a file, rename it with a leading `_`.

Example module:

```nix
{
  flake.modules.homeManager.boatette =
    { pkgs, ... }:
    {
      home.packages = with pkgs; [ ripgrep ];
    };
}
```

## Nix style

- 2 spaces, formatted with `nix fmt`.
- Function arguments: only the ones used, alphabetical: `{ config, lib, pkgs, ... }`. Unused ones fail the checks.
- Lists whose order doesn't matter are alphabetical.
- Comments: few, one line, lowercase, explain why, not what.
- Australian/British spelling in names and prose (`colour`).

## Checking a change

Evaluate what you changed:

```sh
# a system option
nix eval .#nixosConfigurations.aspire.config.<option>
# a home-manager option
nix eval .#nixosConfigurations.aspire.config.home-manager.users.boatette.<option>
# a local package
nix build .#<name>
# final pass
nix fmt
nix build .#checks.x86_64-linux.{formatting,deadnix,statix} --no-link
```

Common errors:

- `attribute '<x>' missing`: misspelt, or only defined in a `let` and not exported.
- `undefined variable '<x>'`: add it to the function arguments.
- `path does not exist` / new file ignored: `git add -N <file>`.
- `option '<x>' does not exist`: wrong name, or in `nixos` instead of `homeManager` (or the reverse).
- deadnix fails: remove the unused argument or binding.

If a check fails, fix the cause. Don't undo the change to something worse that happens to pass.

## Git

- Do not run `git commit`, `git push`, `git merge` or `git rebase` unless the user asks for it.
- When a change is finished, end your reply with the command that would commit it, in a code block, naming the exact files (never `git add -A`):

  ```sh
  git add modules/programs/foo.nix
  git commit -m "feat(foo): add foo with its theme"
  ```

- Message format: `type(scope): summary`, one line, lowercase, no full stop, under 70 characters, no body.
  - Types: `feat` new thing, `fix` broken thing works again, `refactor` change or remove existing config, `perf`, `style` formatting only, `docs`, `revert`.
  - Scope: the file or directory name of the program (`nvim`, `zsh`, `noctalia`).
- One logical change per commit.

## Shell

The shell is zsh: `cat` is bat, `ls` is eza, `cd` is zoxide. Use `command cat` to print a file.
